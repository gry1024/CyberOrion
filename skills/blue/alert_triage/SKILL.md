# 告警研判

1. 确定事件时间、主机、日志源、来源地址和原始摘要，不补全未知事实。
2. 当前角色有 `query_logs` 时，关联同主机、同来源和相邻时间窗；再从网络、进程、文件中选择一种最相关证据，避免无目的全查。
3. 已有 alert ID 时调用 `triage_alert`；用 `search_attack_kb` 或 `lookup_technique` 核对技术编号。
4. 仅凭直接证据给高置信度；证据不足标记 suspicious。确认后把结构化结论交给指挥官调用 `report_finding`。
5. 当前角色缺少所需工具时，在结论中明确请求指挥官派对应角色，不越权替代执行。

最终结论必须包含受影响主机、技术、置信度、证据和建议动作；没有异常就明确说明。
