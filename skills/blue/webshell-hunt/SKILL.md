# WebShell 狩猎

1. 威胁猎人先用 `file_integrity` 检查告警主机和最相关目录；若本次调用只建立首次基线，必须标记证据不足，不能把已存在文件判为正常或直接删除。
2. 对可疑文件记录绝对路径和基线差异；再用 `process_audit` 检查是否存在解释器、反弹 Shell 或关联异常进程。
3. 只有文件内容线索、遥测或进程关系能够坐实时，才调用 `remediate(host, "remove_file", path)`。
4. 文件和关联 PID 由威胁猎人统一处置，避免与响应角色并行重复清理；调用后必须读取复查结果并重新审计一次。
5. 证据不足时保留 suspicious 并请求研判，不删除系统文件或仅凭扩展名清理。

结论列出主机、路径、差异、关联进程和每个实际处置结果。
