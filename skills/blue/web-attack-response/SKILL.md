# Web 攻击响应

1. 哨兵或研判角色用 `query_logs` 建立同一来源、目标路径和短时间窗的请求序列，保留原始 payload、状态码和时间。
2. 区分扫描、尝试和成功：单个特征命中不等于失陷；结合文件、进程或后续请求补充一种证据。
3. 用知识库核对实际技术并把结论交给指挥官调用 `report_finding`；无法判断成功时如实标记 suspicious。
4. 处置角色只负责来源封禁和受害服务加固，必须使用任务中的实际目标，不用示例目标替代；读取复查结果并报告失败。
5. 文件和 PID 统一交给威胁猎人：疑似落地加载 `webshell-hunt`，疑似命令执行加载 `suspicious-process-hunt`，避免并行重复清理。

当前角色无相应工具时请求指挥官派遣，不越权执行或声称已处置。
